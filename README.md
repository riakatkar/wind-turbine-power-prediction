# Wind Turbine Power Prediction using Linear Regression
Project overview
This project explores how wind conditions relate to the electrical power generated by a wind turbine. I used SCADA data from 2018 and built regression models to estimate LV ActivePower (kW) from wind-speed measurements.

The aim was to practise a complete regression workflow: loading data, checking data quality, exploring relationships, selecting features, splitting the data by time, training models, and evaluating predictions.
Dataset
- Source: Kaggle — Wind Turbine SCADA dataset
- File used: T1.csv
- Observations: 50,530 rows
- Period: 1 January 2018 to 31 December 2018
- Original columns:
  - Date/Time
  - LV ActivePower (kW)
  - Wind Speed (m/s)
  - Theoretical_Power_Curve (KWh)
  - Wind Direction (°)
The dataset is downloaded in the notebook using KaggleHub. You may need Kaggle access or credentials configured in your environment.
Project workflow
1. Imported Python libraries and loaded the CSV file.
2. Checked the dataset shape, column types, summary statistics, missing values, duplicate rows, and timestamp order.
3. Converted Date/Time to a datetime column.
4. Used histograms, scatterplots, correlations, and boxplots to explore the data.
5. Created a baseline Linear Regression model using wind speed and wind direction.
6. Used a chronological 80/20 split: earlier observations for training and later observations for testing.
7. Compared the baseline with a model using wind speed only.
8. Added Wind Speed Squared as a simple feature-engineering experiment.
9. Tried Ridge, Lasso, and ElasticNet regression.
10. Compared model metrics, plotted actual versus predicted power, inspected residuals, and used TimeSeriesSplit for time-ordered validation.
Features and target
The main target is:
- y: LV ActivePower (kW) — the actual power output the model tries to predict.
The baseline input features are:
- X: Wind Speed (m/s) and Wind Direction (°).
The polynomial-feature experiment uses:
- Wind Speed (m/s)
- Wind Speed Squared
The theoretical power curve was not included in the initial baseline because it is already a theoretical estimate closely related to power output. This keeps the first model focused on measured wind conditions.
Train/test strategy
The data was kept in chronological order rather than randomly shuffled. The first 80% (40,424 rows) was used for training and the last 20% (10,106 rows) for testing.

This is intended to mimic a future-prediction setting: learn from earlier readings and evaluate on later readings. Time-ordered cross-validation was also explored on the training portion.
Evaluation
The notebook evaluates regression models using:
- MAE: Mean Absolute Error; average absolute prediction error, in kW.
- RMSE: Root Mean Squared Error; gives more weight to larger errors, in kW.
- R²: Measures performance relative to predicting the mean of the test target. It is not classification accuracy.
Previously observed results from this project were approximately:
Model	MAE (kW)	RMSE (kW)	R²
Linear Regression — wind speed only	412.90	552.72	0.8305
Polynomial Linear Regression — wind speed and squared wind speed	414.72	549.23	0.8325
Ridge Regression	414.72	549.23	0.8325
Lasso Regression	414.70	549.24	0.8325
ElasticNet	417.12	558.68	0.8267


These are previously recorded results and should be confirmed by running the notebook from top to bottom in the current environment. The Ridge, Lasso, and ElasticNet experiments were initially run without feature scaling, so those comparisons are preliminary rather than a final ranking.
Main observations
- Wind speed had a strong positive relationship with actual power in the exploratory analysis.
- Wind direction had very weak linear correlation with active power in this dataset.
- The relationship between wind speed and power was not perfectly linear; power output levels off under some operating conditions.
- Adding squared wind speed slightly improved RMSE and R² in the recorded test results, but MAE was slightly worse.
- Linear models can produce physically unrealistic predictions, such as negative power or predictions above the turbine's rated output. Residual plots help reveal these limitations.

Limitations and next steps
- Run all cells in a fresh kernel and confirm the output metrics before treating the results as final.
- Scale the features before making a fairer Ridge, Lasso, and ElasticNet comparison.
- Compare models using the same time-ordered validation strategy.
- Investigate turbine operating conditions and outliers before deciding whether any records should be removed.
- Consider a model that can represent the turbine's nonlinear power curve more closely.
- Do not treat this notebook as a production-ready turbine control or forecasting system.
